## 短命令延迟

每种模式先进行 5 次不计入统计的预热，再通过一个持久 HTTPS 连接串行执行
**100 次 `true` 命令**，不调用模型。P95 使用最近秩法。第二种模式通过后台 `sleep`
任务的租约保持虚拟机。

| 模式 | 客户端 P50 | 客户端 P95 | 客户端最大值 | 网关 P95 | 虚拟机内执行 P95 |
|---|---:|---:|---:|---:|---:|
| 无后台租约 | 3.864 ms | 4.012 ms | 4.057 ms | 2.757 ms | 2.569 ms |
| 持有后台租约 | 3.880 ms | 4.047 ms | 6.989 ms | 2.782 ms | 2.587 ms |

两组均使用预热后的连接。“无后台租约”不等于虚拟机冷启动。数据包括 AgentScope
MCPTool、SDK、HTTPS 和命令执行延迟，不能用于说明虚拟机启动、广域网、并发负载或
故障切换性能。

## 发现的问题与处理

1. **生成的 CA 缺少密钥用途扩展。** Python 3.13 严格 TLS 校验拒绝该证书。
   裸机生成脚本现显式设置标记为 critical 的 CA 约束及 `keyCertSign,cRLSign`，
   重新签发证书后通过，校验始终启用。
2. **鉴权错误导致 SDK 等待。** HTTP 200 携带 JSON-RPC `id:null` 无法关联待完成
   请求。缺失或无效凭证现返回 HTTP 401 和 Bearer 质询，保留请求体读取前的鉴权
   拒绝及原有 JSON-RPC 错误码。真实 SDK 与 Go 回归检查均通过。
3. **凭证文件创建使用了错误的 Python 接口。** 初次初始化将 `opener` 传给了
   `Path.open`；现改用内置 `open`，以独占创建方式写入，权限为 0600。失败尝试创建
   的资源已依据清单删除，随后重新创建全新资源。
4. **工作区缺少项目 README。** 首轮模型按服务端指南读取 `README.md`，产生一次
   工具错误。其代码修复通过了独立检查，但严格验收脚本正确拒绝了该轮。本示例现自带
   工作区 README；上述最终完整运行使用新建沙箱，所有工具调用均无错误。

MCP SDK 2.3.0 拒绝跨源重定向。本次仅验证单网关，不作多网关路由、节点故障或集群
负载能力的结论。未修改 AgentScope 上游代码。
